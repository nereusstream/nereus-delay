# Make dead-letter state internal and replay explicit

Nereus Delay makes `DEAD_LETTER` an authoritative RocksDB terminal state, not a claim that another Broker has accepted a DLQ message. The transition atomically removes reversible current work, releases active capacity, stores an immutable terminal decision core, advances runtime state, and—when configured—creates a stable DLQ Export outbox entry. Already-admitted PUBLISHING/UNCERTAIN obligations cannot be erased by a possible-delivery terminal policy; their IDs/evidence/charges remain as a monotonically shrinking auxiliary summary until independently closed. External export is independently observable and retryable.

## Terminal and export semantics

- A Dead Letter Record contains `delayMessageId`, Message Generation, Destination Binding and capability, original timing, retry policy, attempt history summary, last classified error, last Publish Attempt and evidence, payload descriptor, terminal time, and whether destination publication may already have occurred.
- Eligible `DEAD_LETTER` causes are deterministic message-level permanent failure, retry-policy exhaustion, or an explicit policy that stops an unresolved `UNCERTAIN` attempt. The last choice records possible delivery and atomically persists an `ORDER_OUTCOME_UNRESOLVED` head barrier for a strict Lane; it cannot expose a successor until proof or an audited Break/strict-Close order-loss boundary. Expiration remains the distinct `EXPIRED` terminal state and may create its own operator export when policy requests it. Credential outages, capability drift, target unavailability, and executor saturation block a Lane; they do not misclassify every queued message as permanently bad.
- Optional DLQ Export uses the Protocol Registry's stable `SHA-256("nereus-delay-dlq-export-id\0" || DelayMessageId[41] || generation:u32be || terminalRevision:u64be)` and a dedicated system Lane with reserved bounded resources. Its state is the closed set `NOT_CONFIGURED`, `PENDING`, `PUBLISHED`, `UNCERTAIN`, or `FAILED_PERMANENT`;Nereus Delay has no manual `ABANDONED` shortcut. The terminal transition persists one canonical export envelope, `physicalAttemptNo=1`, and first-export time equal to the terminalizing record's Broker persistence time before external I/O. Every callback/timeout changes the outbox only through an exact `DLQ_EXPORT_RESULT(ATTEMPT_OUTCOME)` keyed by `(dlqExportId, physicalAttemptNo)`; later proof uses an evidence-ID-bound resolution. A retry is authorized only after the preceding result is source-ordered, uses the pinned policy's separate DLQ retry/jitter domain, and increments the checked attempt number while reusing the same external envelope/ID. Every payload/object/binding reference and byte needed to reproduce it remains charged and protected until a qualifying result is floor-covered.
- The exporter is at-least-once unless its own Destination Profile selects a stronger capability. Duplicate exported records are therefore possible and are deduplicable by `dlqExportId`. Export failure never reactivates or deletes the business message.
- User query returns the business terminal state and DLQ Export state separately. Alerts cover aged pending/uncertain exports and permanent export failure.

## Replay semantics

`ReplayDeadLetter` is an authenticated Control Operation whose exact target is emitted as signed `REPLAY_DEAD_LETTER` System Mutation to the original Shard Log partition. It requires the expected Message Generation and Message Control Version, a new `deliverAt`, a bounded `expireAt` and pinned retry policy, possible-duplicate acknowledgement when applicable, and deterministic `systemMutationId + mutationHash`. On successful application it creates `generation + 1`, preserves payload and Destination Binding, consumes fresh quota, and creates a new timeline entry with an empty obligation set. Any old open `AttemptObligationRef` remains only in the old terminal record's auxiliary summary/ledger and is never copied into or allowed to affect the new runtime index; its exact encoded key avoids an Owner-Epoch scan, and late old evidence only retires old charges. The old terminal decision and export remain immutable audit history, while that auxiliary summary may shrink monotonically. Retry/response loss uses the same Control Operation/mutation identity and is queried through `ControlOperationReceipt`, not Command receipt.

The terminal mutation fixes `deadLetterReplayUntil = terminalRecordBrokerPersistenceTime + pinnedReplayWindow`. Replay is accepted only if its own Broker persistence time is not later, the preceding signed `TIME_FENCE` has not closed that deadline, exact retained dependencies remain protected, and other state/quota checks pass. Application lag and GC timing do not change eligibility. A generation dead-lettered from `UNCERTAIN`, or whose terminal summary still has an open possible-delivery obligation, may already be visible at the destination; replay therefore additionally requires `allowPossibleDuplicate=true`. replay cannot change payload or semantic destination—those require a new Schedule identity or a future migration protocol.

## Retention

Payload, terminal history, capability evidence, and replay metadata remain protected until the replay deadline is source-closed and every permitted Recovery Checkpoint contains that closure. DLQ Export dependencies additionally remain until a logged `PUBLISHED` or closed-policy `FAILED_PERMANENT` result is floor-covered. `RESOURCE_RETIRE_INTENT` and delete confirmation make GC replayable. After guarded GC, query reports terminal summary retention separately from payload availability, and replay is no longer permitted. Route retirement includes every replay-eligible terminal generation. Neither external DLQ retention nor successful DLQ Export is used as recovery proof for the shard.
