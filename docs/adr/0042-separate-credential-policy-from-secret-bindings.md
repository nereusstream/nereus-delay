# Separate immutable credential policy from rotatable secret bindings

Nereus Delay V1 separates immutable Profile semantics from live credential selection. A Destination or Object Store Profile hashes the exact credential authorization-scope/policy and binding-protocol version, but never the current secret reference or generation. Each service-owned reference generation is an immutable private `CredentialBindingV1`; a checked `CredentialBindingHeadV1` selects current and a monotonic `CredentialBindingProtectionV1` protects issued capabilities.

## Decision

- Profile publication atomically creates an already-verified immutable generation-1 binding, Head revision 1 and protection record before the Profile can become active. No Schedule or runtime channel may observe a Profile that requires credentials but has no valid agreeing Head/generation.
- `RotateEquivalentSecretReference` fixes the expected Head generation/binding-digest/revision triplet, exact next generation, private new reference and its digest, and a full signed `CredentialEquivalenceAttestationV1`. The proof binds Profile/generation/reference digest/scope digest, resolved immutable provider secret-version/public-fingerprint digest, verifier/key version, Trusted-UTC acceptance deadline and exact authenticated probe-evidence digest. References must be immutable version-qualified, never `latest` or a mutable alias. The verifier must prove the same principal, resource set, permitted operations and other immutable authorization-scope policy; an operator assertion alone is not evidence. A changed scope requires a new Profile version.
- Binding Head CAS is the control-plane effect boundary. One transaction verifies expected Head generation/digest/revision and catalog capacity, creates exactly the checked next immutable generation/protection and advances Head. A lost response rereads those exact objects; retry uses the same Prepared Control Operation. The private reference is redacted from public results and ordinary audit export, which expose only safe digests/generation.
- Lane activation/renewal resolves the immutable reference and atomically compares the current Head while extending managed-channel protectionUntil; only then may it issue the bounded `DESTINATION_CHANNEL` Credential Use Lease embedded in channel/certificate. Every first physical Producer call checks that lease and loaded fingerprint locally and reaches library ownership inside `maximumCredentialAuthorizationToProducerCallAge`, with no per-message Oxia read. Protection-before-rotation authorizes calls only until exact lease expiry; rotation-before-protection/renewal rejects the stale issuer. The rotation notification removes affected READY early, but old binding material remains protected until lease expiry, every physical/zombie request, fenced teardown and the configured quiescence horizon have all elapsed.
- Equivalent rotation is not emergency revocation and does not claim remote Broker fencing. Immediate stop requires the source-ordered Lane gate plus the applicable Broker/credential revocation mechanism, and any race already past local authorization remains a possible delivery.
- AUTO_FAST has no Shard Ready Certificate. Its exact signed `NativeCapabilitySnapshotV1` is a short-lived authorization lease containing safe binding generation/digest/fingerprint fields; one transaction compares the current Head triplet and monotonic max-CASes `CredentialBindingProtectionV1.nativeCapabilityProtectionUntil`. Upload-handle issuance analogously protects its expiry. Protection-before-rotation authorizes the bounded capability; rotation-before-protection rejects the stale issuer. Equivalent rotation leaves an exposed capability valid only through its signed expiry, while emergency Broker/credential revocation can still leave a provider/Producer-owned request uncertain.
- Object Store Adapter activation/renewal uses the analogous Head-compare/protection transaction to issue a bounded `OBJECT_STORE_ADAPTER` Credential Use Lease. Calls check the lease/fingerprint locally and reach provider ownership inside the configured age bound. Binding failure is operation-scoped: handle/attestation is retryable, payload fetch revokes only its Claim, checkpoint/restore waits under the existing recovery-margin gates, and GC retains its protections. It never becomes a destination-backlog source pause or proof that an object is absent.
- Rotation is capacity-gated. If another protected historical binding would exceed `maxRetainedBindingGenerationsPerProfile`, the CAS is rejected with `HARD_QUOTA_EXCEEDED`; no in-flight channel, provider request, upload handle or audit-required generation is deleted to make room.
- The rotation is runtime-only: it changes neither Profile semantic hash, Destination Lane ID, applied Destination Binding, Command result nor source order. Command application and unrelated Lanes continue while affected Lanes recover their channels.

## Consequences

Credentials may rotate without rerouting long-delay messages, while a privilege expansion cannot masquerade as a transparent rotation. Recovery can distinguish semantic identity from current runtime authority, and no circular rule requires an immutable Profile hash to change in order to update the secret it references.
