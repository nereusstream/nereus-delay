## 3. H0：立即关闭两条未闭环的 native physical reachability

### 3.1 目标

H0 在 NDIP 尚未 Accepted 时完成，用于保证：

- 任何 `actionAt < deliverAt` 的 Managed Pulsar request 不会取得 physical admission、创建
  message builder、获取 Producer ownership 或调用 target send；
- 任何通过现有前置校验的 AUTO_FAST native request 不会进入 `transport.send`、`sendFrame`
  或 Producer ownership。

### 3.2 Managed 三层门

第一层位于 `WorkerPhysicalPublishExecutor.submit(...)` 的 identity 校验之后、现有
`checkGate(...)` 之前，因此也早于 `physicalAdapter.submit(...)` 和任何 physical admission 获取：

```text
request.actionAtEpochMs < request.deliverAtEpochMs
    -> DEFINITELY_NOT_PUBLISHED
    -> CAPABILITY_UNAVAILABLE
    -> enqueue existing source-log Outcome handoff
    -> do not acquire physical admission
    -> do not delegate
```

第二层位于 `PinnedPulsarDestinationAdapter.publishOpen(...)` 内、
`timingPolicy.validate(...)` 与 transport request/call 之前；第三层位于
`PulsarClientArtifactDestinationTransport.publish(...)` 内、`producer.newMessage()` 之前。

精确生产文件：

- `src/main/java/com/nereusstream/delay/ownership/WorkerPhysicalPublishExecutor.java`
- `src/main/java/com/nereusstream/delay/adapter/PinnedPulsarDestinationAdapter.java`
- `src/real-pulsar/java/com/nereusstream/delay/transport/PulsarClientArtifactDestinationTransport.java`

约束：

- Worker 外门必须让 physical admission/reservation acquisition 次数为零；
- adapter/real transport direct bypass 也必须 fail-closed；
- ordinary `actionAt == deliverAt` 行为不变；
- Kafka 行为不变；
- 不修改 `BoundedDestinationPublishAdapter` 或 `PulsarDestinationTimingPolicy`。

### 3.3 AUTO_FAST 两层门

第一层位于 `PinnedPulsarNativeSubmissionAdapter.submitOpen(...)` 已有
resource/signature/time/credential/attempt/request 校验之后、`transport.send(request)` 之前。
对原本将发送的有效 request 返回：

```text
NativeDefinitelyNotQueued
stableCode = CAPABILITY_UNAVAILABLE
proofKind = LOCAL_BEFORE_PRODUCER_OWNERSHIP
```

保留所有 malformed/resource/signature/expiry 等更早的精确错误；本地 H0 不得伪装为
`PULSAR_GUARD_REJECTION`。

第二层位于 `PulsarClientArtifactSendTransport.send(PulsarNativeSendRequest)` 内、
`sendFrame(...)`/`producer.newMessage()` 前，返回
`PulsarSendResult.DEFINITELY_NOT_PERSISTED / CAPABILITY_UNAVAILABLE`。不得误伤 command-ingress
的 `PulsarSendRequest` overload 或 ordinary source/command transport。

精确生产文件：

- `src/main/java/com/nereusstream/delay/adapter/PinnedPulsarNativeSubmissionAdapter.java`
- `src/real-pulsar/java/com/nereusstream/delay/transport/PulsarClientArtifactSendTransport.java`

## 4. 已关闭的设计决策

以下问题已有唯一答案，实施者不得在编码中重新选择：

| ID | 契约 | 最终答案 |
|---|---|---|
| R1 | policy/contract/path authority | Schedule/Message 保存 requested policy；Admission/Prepared 保存 actual contract；路径由既有 outer union 表达，不增加 `DispatchMode` |
| R2 | lease 物理线性化点 | Admission 冻结；Managed 在 durable `OWNERSHIP_STARTED` 前、AUTO_FAST 在 transport call 前再次验证；ownership 后保持 unknown |
| R3 | AUTO_FAST target timestamp | 删除 clock shift；native timestamp 精确等于业务 `deliverAt` |
| R4 | reset gate 位置 | Gate B PASS 允许 H1-H6 与 exact disposable tests；真实 persistent deployment 才运行 G0，Gate C PASS 允许 SHADOW，Gate C + SHADOW requirements + signed manifest 允许 ENABLED |
| R5 | schema activation | 一个 `ArtifactGenerationSet` 复用现有 Worker capability、eligible reader set 与 source-ordered activation |
| R6 | record/command hash 关联 | Admission 绑定 template；Journal 后产生 final record；record/command hash 为不同 domain，通过 source-locked deterministic encoder 与 golden vectors 关联，不要求 hash 相等 |
| S1 | runtime lead 对 Lane head 的影响 | 同一 Lane/DRR authority 维护 ordinary/native 双内部 head；不得创建第二 scanner/fairness authority |

exact field table、stable code、hash domain 和类级落点以
[`04-代码级目标设计.md`](04-代码级目标设计.md) 为准。

## 5. Contract 与 closed schema 切片

### 5.1 新增/替换语义类型

新增 current canonical type：

- `NativeDeliveryPolicy`
  - `FORBID`
  - `ALLOW_MANAGED_HANDOFF`
  - `ALLOW_AUTO_FAST_AND_MANAGED_HANDOFF`
- `DeliveryContract`
  - `NEREUS_MANAGED_NOT_BEFORE`
  - `PULSAR_NATIVE_DELIVERY`
- `HandoffPolicySnapshot`
- `PulsarPreparedRecord`
- Pulsar key closed oneof：`NONE / UTF8 / BINARY`
- closed canonical sorted property entry/list；
- `ArtifactGenerationSet`。

修改 current canonical type：

- `CanonicalScheduleIntent`
- Schedule command/body；
- durable Message value；
- `DestinationProfileSemantic`
- `DeliveryCapabilitySemantic` / `TimingCapability`
- `PreparedPublishDescriptor`
- `PublishAdmissionBody`
- `NativePreparedDelivery`
- `PulsarSendAckEvidence`
- query/outcome projection。

### 5.2 Profile

直接替换 fixed `handoffLeadMs` 语义为最大值：

```text
maxHandoffLeadMs >= 0
Kafka -> 0
Pulsar ordinary-only -> 0
native-enabled Pulsar -> bounded positive value
```

runtime `effectiveLeadMs` 必须小于等于 Profile max；越界返回
`POLICY_OUT_OF_BOUNDS`，不做 `Math.min`。

### 5.3 required message policy

- direct SDK、Gateway、Command codec 和 replay 都必须显式携带 policy；
- API 未显式选择时，SDK writer 写 `FORBID`；
- wire 缺失不是默认值，而是 malformed/unsupported bytes；
- query 返回 requested policy 与 actual delivery contract，避免审计歧义。

### 5.4 descriptor

在新的 descriptor generation 中绑定：

- actual contract；
- full optional Handoff snapshot；
- event time；
- closed Pulsar key；
- sorted unique caller properties；
- ordering key；
- 八个 reserved identity/time 值，以及 final record 必须追加第九个
  `nereus.delay.prepared_hash` 的规则；
- target resource/partition；
- profile refs/hashes；
- attempt identity；
- timing；
- `PulsarRecordTemplate` 与 `recordTemplateHash`；
- exact `ArtifactGenerationSet` digest。

descriptor 不得包含 Journal mapping、sequence authority、`sequenceId`、最终
`preparedRecordHash` 或 SEND/ACK hash；这些值在 Journal mapping 后才存在。

不得增加 `nereus.delay.dispatch_mode`。

### 5.5 codec gates

- exact field order/number/type；
- canonical re-encode equality；
- unknown enum/generation reject；
- duplicate/unsorted property reject；
- UTF8 key 验证、binary key round-trip、oneof conflict reject；
- absent/present event time；
- property reserved namespace collision reject；
- fixed nine reserved fields and values；
- hash domain separation；
- golden vectors and mutation corpus。

## 6. Runtime policy authority 切片

### 6.1 snapshot canonical schema

固定字段、长度上限、signature algorithm、domain separator、key generation 和 scope digest。
scope 至少绑定：

- tenant/route scope；
- destination Profile ref/semantic hash；
- capability Profile ref/semantic hash；
- target resource incarnation；
- physical partition 或明确的 bounded partition set；
- 可授权 path mask；
- ordering restriction。

如果 scope 允许多 partition，canonical list 必须 sorted/unique/bounded。

### 6.2 Oxia head

Oxia 保存当前 head 与发行状态，不作为历史 snapshot store：

```text
generation
mode
currentSnapshotDigest
effectiveDisabledAfter
CAS revision
```

Candidate/Claim 读取 current head；Admission 做 CAS-stable reread/验证并把完整 snapshot 写入
source log。Admission replay 不查历史 Oxia value。

### 6.3 lease 验证

按已关闭的 lease 契约：

- Candidate：trusted interval 证明 snapshot 当前可用；
- Claim：再次证明 head/scope/generation；
- Admission：冻结完整 snapshot，`earliest >= validFrom` 且 `latest < validUntil`；
- physical send：Producer ownership 前再次要求 `latest < validUntil`；
- interval 跨界：`TIME_SAMPLE_REQUIRED`，不触碰 Producer；
- ownership 已开始：不再因 lease 到期把 unknown 当作 definitive rejection。

### 6.4 Disable

控制面：

1. CAS 将发行状态改为 DISABLED；
2. 停止签发 ENABLED snapshot；
3. 计算所有未过期 lease 的最大 `validUntil`；
4. 到达上界后核对无 late ownership；
5. 发布/声明 `EFFECTIVE_DISABLED`。

测试 clock interval、issuer key rotation、stale cache、Oxia unavailable、CAS conflict 和 Worker
restart。

## 7. Scheduler、Claim 与 Admission 切片

### 7.1 candidate

```text
ordinaryHeadAt = max(deliverAt, retryEligibilityAt)

nativeHeadAt = deliverAt - maxHandoffLeadMs
    only for initial-attempt + explicit native opt-in + Pulsar + BEST_EFFORT
```

同一 Lane、同一 DRR/fairness authority 维护两个内部 head，并在同一个 Store WriteBatch 中原子
更新。ordinary head 始终可选；native head 到点只触发一次 process-local eligibility 计算：

```text
mode != ENABLED or effectiveLeadMs == 0
    -> skip native; ordinary head remains

0 < effectiveLeadMs <= maxHandoffLeadMs
    -> candidateAt = deliverAt - effectiveLeadMs
```

静态 native head 只是最早唤醒边界，不是发送授权。不得用单一持久 head 保存一次动态
`candidateAt`，否则 policy disable/lead 缩小时会阻塞同 Lane 更早的 ordinary due；也不得创建
第二套 timeline/scanner 或 fairness authority。

### 7.2 trusted-time state

当 interval：

- 完全早于 candidate：返回未来 `WaitUntil`；
- 跨 candidate：`TIME_SAMPLE_REQUIRED`；
- 完全位于 candidate 与 deliverAt 之间：可继续 native eligibility；
- 跨 deliverAt：`TIME_SAMPLE_REQUIRED`，随后可 ordinary；
- 完全晚于 deliverAt：ordinary due。

所有 backoff 必须 monotonic、bounded、可观测，禁止 past wakeup 热循环。

### 7.3 Claim

- native candidate Claim 仍可逆；
- Cancel/Reschedule 在 Admission 前按现有线性化点工作；
- Claim 保存用于 Admission reread 的 policy head precondition；
- head 漂移、lease 过期、policy disable、ordering mismatch 时释放 Claim 并保留 ordinary due。

### 7.4 Admission

ordinary 和 native 使用 closed union/equality：

| Field | Ordinary | Managed Handoff |
|---|---|---|
| contract | `NEREUS_MANAGED_NOT_BEFORE` | `PULSAR_NATIVE_DELIVERY` |
| actionAt | `deliverAt` | `deliverAt - effectiveLeadMs` |
| policy snapshot | absent | full ENABLED snapshot |
| Pulsar deliverAt branch | absent | exact business `deliverAt` |
| ordering | current supported modes | `BEST_EFFORT` only |

Admission canonical decode 必须验证所有 cross-object equality。

## 8. 无损 physical request 与 record encoder 切片

### 8.1 request 边界

替换 flat `DestinationPublishRequest`。Admission 先冻结 `PulsarRecordTemplate`，并由 template
产生 `recordTemplateHash` 和 descriptor/`preparedPublishHash`。新边界必须把 validated
descriptor、resolved payload、source position/admission identity 无损传给 Journal/adapter；
resolved payload 不得改变 descriptor 中 payload identity/hash。

禁止在 Worker 中再次从零拼一套 metadata map。

### 8.2 deterministic Pulsar record

Managed 在 Admission 之后执行 Journal `appendOrReuse`，取得 fixed mapping/sequence authority，
随后才由 validated descriptor + resolved payload + mapping 构造 final `PulsarPreparedRecord`。
AUTO_FAST 使用 closed `PRODUCER_ASSIGNED` sequence branch，不使用 Managed Journal。record 字段
至少包括：

- target/partition；
- payload bytes/hash；
- key oneof；
- ordering key；
- caller + reserved properties；
- event time；
- closed sequence authority；
- ordinary/native deliverAt branch；
- admission/prepared identity。

encoder 产出 canonical bytes 和 `preparedRecordHash`。transport 只消费该 record，不再解释
business policy。固定时序为：

```text
RecordTemplate
  -> recordTemplateHash
  -> descriptor / preparedPublishHash
  -> Managed Journal mapping + fixed sequence
  -> final PulsarPreparedRecord
  -> preparedRecordHash
  -> ownership
  -> actual SEND command
```

因此 Admission/descriptor 不能预先绑定 final `preparedRecordHash`。

### 8.3 builder projection

ordinary：

```text
producer.newMessage()
    .value(payload)
    + managed .sequenceId(sequenceId) or AUTO_FAST producer-assigned branch
    + key/order/properties/eventTime
    .sendAsync()
```

native：在同一投影上增加：

```text
.deliverAt(deliverAtEpochMs)
```

所有 optional field 必须有 closed absence semantics；不得把 empty 与 absent 混为一谈。

## 9. Production Attempt Journal 切片

### 9.1 resource contract

- Nereus-owned non-compacted Pulsar topic；
- partition 与 Delay Shard 绑定；
- exact resource incarnation；
- retention 覆盖 unresolved mapping、checkpoint floor 和 recovery window；
- cursor/reader 证明 contiguous replay；
- journal producer/consumer identity source-locked。

### 9.2 mapping lifecycle

```text
UNMAPPED
  -> appendOrReuse MAPPED
  -> Broker ACK mapping position
  -> persist/associate attempt ledger state
  -> construct final record with fixed sequence
  -> revalidate frozen lease
  -> append durable OWNERSHIP_STARTED
  -> target send
  -> PUBLISHED evidence
     or UNCERTAIN resolution
     or durable RETIRED_NOT_PUBLISHED proof
```

同一 Producer 有 unresolved lower sequence 时阻塞更高 sequence。retirement 只有在确定未发布
证据成立且 `OWNERSHIP_STARTED` 尚未写入时才能清除阻塞；marker 后没有 definitive persistence
proof 的结果必须保持 `UNCERTAIN`。

### 9.3 crash matrix

测试：

- mapping append 前 crash；
- append 已提交但 client response 丢失；
- mapping replay 后 target send 前 crash；
- durable ownership marker 前/后 crash；
- send command ownership 前 definitive failure；
- ownership 后 response 丢失；
- target ACK 后 source outcome 前 crash；
- Journal cursor/retention gap；
- Producer generation change；
- resource incarnation change。

## 11. AUTO_FAST 切片

AUTO_FAST 继续使用独立 prepared/outcome union，但接入 required message policy 和同一个产品
contract。

### 11.1 eligibility

- `FORBID`：不准备 native candidate；
- `ALLOW_MANAGED_HANDOFF`：跳过 AUTO_FAST；
- `ALLOW_AUTO_FAST_AND_MANAGED_HANDOFF`：满足现有 zero-I/O/P1 prerequisites 后才准备；
- ordering 非 `BEST_EFFORT`：`ORDERING_CAPABILITY_UNAVAILABLE` 或 managed fallback，按 API
  contract 固定；
- ownership 前失败：fallback Managed；
- ownership 后 unknown：不 fallback。

### 11.2 timestamp replacement

按已关闭的 timestamp 契约：

- 删除独立 clock-shift correctness 字段/计算；
- `NativePreparedDelivery` 只绑定 exact business `deliverAt`；
- P1 target record 使用相同 timestamp；
- Broker clock 风险进入 product diagnostics，不授予 capability。

### 11.3 evidence/recovery

- AUTO_FAST 不使用 Managed Attempt Journal；
- actual SEND/ACK hashes 使用新的 closed evidence contract；
- `NATIVE_ENQUEUE_UNCERTAIN` 只能查询或 evidence resolution；
- 任何自动 resend/fallback after ownership 都是 gate failure。

## 12. Data reset / migration 切片

### 12.1 G0：persistent deployment 前的 read-only DataResetAssessment

G0 core 已实现，但不作为 H1-H6 前置。只有准备接触 existing/staging/production persistent
environment 时才运行；当前没有真实 deployment，状态为
`NOT_APPLICABLE_FOR_IMPLEMENTATION / PENDING_DEPLOYMENT`，不得构造虚假 scope、placeholder
PASS 或 receipt。reader/evaluator 对明确 scope 内的 runtime resources 只能读取，唯一允许的写入
是本地 assessment receipt。不得创建 runtime Producer/Writer、清理或迁移数据、drain obligation、
换 incarnation、升级 Worker 或签发 policy。Assessment 必须：

- 列举每个 environment、tenant、route、shard、resource 和 observation time；
- 标识外部用户数据保留义务；
- 列举并分类当前所有 publishing/uncertain，但不冒充切换时的 zero-obligation proof；
- 评估每个旧资源是否可丢弃、换 incarnation 或必须迁移；
- 固定可枚举、可整体升级的参与切换 Worker 集合，但不要求其已支持未来 generation；
- 绑定 exact NDIP package digest、source baseline、scope digest 和 evidence digests。

closed outcome：

- `PASS_DIRECT_REPLACE`：没有外部兼容/迁移义务，所有旧内部状态均可直接丢弃或换
  incarnation，且没有必须跨 generation 保留的未知 obligation；
- `PASS_RETAIN`：所有需保留状态都明确 `RETAIN_COMPATIBLE`；
- `MIGRATION_REQUIRED`：先补齐并执行有界一次性迁移，形成 completion receipt；
- `INCOMPLETE`：证据、scope、权限或身份不完整，保持 fail-closed。

上述 outcome 只形成 RESET / RETAIN / MIGRATE candidate。独立 Gate C 必须绑定 exact
environment/classification/scope、Assessment receipt 和 gate receipt；只有 RESET、RETAIN 或已完成
迁移的 MIGRATED resolution 才能进入 SHADOW。Assessment 不能授权 mutation、SHADOW 或 ENABLED。

### 12.2 signed manifest

`DataResetManifest` canonical schema 至少包括：

- deployment/tenant/route/shard scope；
- baseline commit；
- reset generation；
- artifact generation set + digest；
- exact resource identity/incarnation list；
- cleanup/fresh-resource evidence；
- obligation zero proof；
- eligible Worker set + capability evidence；
- created trusted-time evidence；
- activation window；
- issuer key generation；
- manifest digest/signature。

Manifest 由 H6 实现，并在实际 cutover window 重新证明 zero external retention、zero unresolved
obligation、fresh/clean resource incarnation 和 all eligible Workers exact generation。Assessment
receipt 不能替代其中任何一项。

### 12.3 startup/assignment gates

Worker 在打开 Store、消费 source log 或获得 assignment 前验证：

- manifest signature/digest；
- scope；
- reset generation；
- local supported generation set；
- resource incarnation；
- route/shard identity。

不匹配时禁止启动/assignment，不允许“先运行再逐步收敛”。

### 12.4 one-time migration fallback

若 assessment 发现需要保留数据：

- 暂停 direct reset；
- 在 NDIP 中补齐一次性迁移输入、输出、checkpoint、审计证据和退出条件；
- 迁移完成后删除旧 reader/writer；
- 不保留永久并行格式。

## 15. 提交切片建议
