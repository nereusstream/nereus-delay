# NDIP 生命周期与认证源码权威分层代码级目标设计

- 提案状态：`Accepted`
- 设计范围：repository governance and source identity only
- runtime 语义变更：`none`

## 1. acceptance verifier

`scripts/verify-ndip-package.py` 必须：

- 同时支持 legacy NDIP-1 generation-2 receipt 与 NDIP-2 generation-3 receipt；
- 对 proposal/path set/schema/decision/authorization 使用 closed validation；
- 提供 `--source-commit` 只读模式，从 Git object database 重算历史 package；
- 要求当前保留的 receipt bytes 与该 commit 中 receipt bytes 完全一致。

## 2. implementation verifier

`scripts/verify-ndip-implementation.py` 必须验证：

- closed receipt root 和 nested object keys；
- NDIP-2 Accepted governance receipt digest；
- NDIP-1 历史 Accepted receipt 与 transition commit；
- current Implemented normative package digest；
- certified runtime source digest；
- historical certification tooling digest；
- disposable 24/24 + 3/3 和 persistent full-chain summary digests；
- final `DISABLED`、zero active lease/send 与 `productionAuthority=false`；
- deployment/performance/production 三个 `SEPARATE_FUTURE_WORK` 边界。

verifier 默认还比较当前 runtime scope。`--historical-only` 只验证历史 closure，
用于未来 runtime 已合法演进但需保留 NDIP-1 lifecycle history 的情况。

## 3. runtime source projection

`build.gradle` 中两个治理 block 使用 closed projection marker：

1. running source identity 解析 block；
2. NDIP documentation/receipt verification block。

它们在 certified commit 和 current checkout 中都被同一固定 token 代替后再参与 digest。
除这两个范围外的 `build.gradle` bytes 必须 exact equality。receipt 不能提供
exclude path 或 projection range，避免通过收缩 scope 绕过门禁。

## 4. runnable artifact identity

`generateRunningArtifactIdentity` 先调用 implementation verifier 解析当前 runtime source。

- 如果 scoped digest 精确匹配，resource 中 `sourceCommit` 写入 receipt 绑定的
  certified commit，`trackedSourceClean=true`；
- 如果不匹配，resource 仍写入 actual HEAD 和全量 tracked cleanliness，旧 Gate C
  会按原规则 fail-closed。

这不修改 `RunningArtifactIdentity` 或 `PersistentStagingActivation` 的 runtime contract，也不伪造
新 certification。它只把“当前仓库 HEAD”替换为经闭合 verifier 证明的“当前
runtime source authority”。

## 5. fail-closed tests

至少覆盖：

- receipt unknown/missing field；
- runtime file content drift；
- runtime path add/remove；
- build dependency bytes drift；
- governance block-only drift remains equivalent；
- README/execution-record-only drift remains equivalent；
- evidence digest mismatch；
- `productionAuthority=true` rejection；
- deployment/performance/production 被写成 complete 时 rejection。
