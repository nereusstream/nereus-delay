Status: Draft / 契约冻结；切片验收见 progress.json 和 evidence/b2-results.json。

本文补全 §08 的 authorityPolicyRef 与发放/关闭 wire。B2 按原设计 §17.3 验收设计、
字段及拒绝契约；C1 承担实际 source 原子应用和权威后端装配，C2 承担通道运行。

## 1. 不可变 TargetMembershipPolicy

完整策略由可信服务端审批，不能将请求里的自报对象或计算出的 hash 当作审批。
`TargetMembershipPolicy` schema=1，reserved NV type=23，meta key 为
`10 01 + digest[32]`；仍使用七个 CF，活动 format 1 / NV 1..11 不变。

| 字段 | canonical 内容 |
| --- | --- |
| 1 | uint32 schema=1 |
| 2 | 非零 tenantScope[32]，绑定成员所属认证 tenant |
| 3 | 完整 Destination ProfileRef，ID ≤256 bytes，semanticHash 非零 |
| 4 | 非零 requiredDispatchRef[32]；发放时从精确 Profile/capability 重算 |
| 5 | 完整 offered TargetDispatchCompatibility |
| 6 | 完整 TargetControlScope；source Shard、Target 及所有额外 control/permit 组 |
| 7 | uint32 credential mode=1，COMMON_AUTHORIZED_PROVIDER；其他值拒绝 |
| 8 | 非零 controlResourceScope[32]，绑定认证 Control actor 的资源授权范围 |
| 9 | SHA-256(`nereus-delay-target-membership-policy\0` + fields 1..8) |

tenantScope 与 Control 资源范围是两个不同的身份，不能相互替代。mode=1 允许通过
该 offered authorization scope 下任一合法共同 provider 执行，不要求成员自己的
credential head 当前可用。额外的私有凭据依赖必须进入 AUTHORIZATION_CONTROL scope；
完整 control/permit 集合和 offered 保证必须由审批权威核实，codec 无法推断集合完整性。

策略不可原地修改；变更产生新 digest，并重新授权后续 grant。旧完整策略、注册记录、
签名公钥及审批证据必须保留到引用它们的 source replay、binding、reservation、attempt、
checkpoint/recovery 保护全部解除。停发 grant 不删除历史策略，也不撤销旧 attempt。
PolicyAuthority 按精确 policyRef、完整 SourcePosition 和 GRANT/CLOSE 操作返回该位置
获准使用的完整策略；查不到或对象不同拒绝，后端失败传播为可重试基础设施失败。
审批证明还必须覆盖物理 Target、source 路由、tenant/Profile 及全部独立门；C1 禁止把
解码器或无条件返回请求对象的 lambda 装配为生产审批权威。关闭操作可依据保留的历史
策略单独获准，即使该策略已不允许新 grant。

`requireRegistration` 重建并比对 §08 的全部八个 pre-append 字段，包括精确策略 digest
与 operationId；只重算 hash 不能隐藏遗漏组或换 Profile。Store 解码核对 exact key、
完整对象和 source Shard。集合条数及嵌套字节上限在解码前检查。

## 2. Control 请求、签名与 source body

| 操作 | ControlOperationKind / Request oneof tag | ApplyShardControl kind / ControlPayload tag |
| --- | --- | --- |
| GRANT_TARGET_MEMBERSHIP | 16 / 16 | 15 / 15 |
| CLOSE_TARGET_MEMBERSHIP | 17 / 17 | 16 / 16 |

Request 分支为闭合 canonical protobuf。GRANT：field 1 完整 policy、field 2 完整
registration；CLOSE：field 1 完整 policy、field 2 非零 grantRef[32]、field 3 完整
ControlReason。外层使用既有 ControlOperationRequest 格式及上述 oneof tag。
两操作都要求 TENANT_POLICY_ADMINISTRATOR 和 PLATFORM_OPERATOR，认证 actor/role-set/
resource-scope 必须与 PreparedControlOperation 一致，并通过完整目标范围证明。

PreparedControlOperation 只能包含一个精确 source SHARD target，targetIndex=0，
必须含目标 mutation ID/hash。它沿用现有不可变 ControlTargetRegistrationAuthority
登记协议；source verifier 查找精确 operationId 并逐 bytes 比较完整已登记对象。
Prepared 与 SystemMutation 均用 source 位置获准的 Control 公钥验证 Ed25519 签名；
历史 key 的 uint32 bit identity 必须保留，包括 raw -1 对应 4294967295。
SystemMutation 的 CONTROL author 三个身份字段必须等于 Prepared author；仅有相同
mutation ID/hash 不能替代这项检查，因为既有 hash/ID 公式没有包含 author。

新 `TargetMembershipControlBody` 仍使用 SystemMutationType.APPLY_SHARD_CONTROL=1：

| 字段 | 内容 |
| --- | --- |
| 1 / 2 / 3 | ShardSubject / type=1 / 非负 retryUntilEpochMs |
| 10 | 完整 ControlRef：operationId、targetIndex=0、requestHash |
| 11 / 12 | 新 control kind 15 或 16 / semanticVersion=1 |
| 13 | semanticHash：SHA-256(`nereus-delay-target-membership-control\0` + u16be(kind) + request branch bytes) |
| 14 | GRANT 必须缺失；CLOSE 必须存在且为 0，表示首次 closure 的空前态 |
| 15 | ControlPayload 单分支，tag=kind、内容为完整 request branch |

requestHash、ControlRef logical identity、SystemMutation mutationHash/ID 沿用 Registry
原公式。新独立向量锁定两种操作的每一层 bytes/hash；body 不引用未来 source offset。
GRANT registration 的 operationId 必须等于 ControlRef。CLOSE 即使已有 closure 也必须
保留首次 closedAt，field 14 不授权覆盖历史关闭位置。

## 3. 首次应用与重放顺序

`TargetMembershipControlVerifier.verifyFirstApplication` 是无写入规划器。C1 source
applier 必须先处理既有 SystemMutationResult 去重：已应用或已拒绝记录返回原结果，
不能把旧注册在较晚 source 位置再次送进首次应用器并生成另一个 grant。

1. 验证 source/Shard/body/logical/request 的精确关联、签名 retry deadline、双签名、
   author、角色、目标范围、不可变登记记录及完整已批准 policy。
2. GRANT：从 registration、实际 mutationHash 和实际完整 SourcePosition 派生 grant；
   重算精确 Destination/capability 的 required 投影，再比对完整物理 Target/offered。
3. CLOSE：解析完整旧 grant，核对原 policy，要求 source 严格晚于 activation，且属于
   同一完整物理 source。已有 closure 不允许被未来快照、同 offset 不同 bytes 替换。
4. 返回 GRANT / CLOSE / ALREADY_CLOSED 的完整前后态；不写 Store、不推进 source。

C1 必须把 Key/Policy/actor/scope/Profile/registration/membership 输入绑定到同一受
Owner、Store、source fence 保护的快照，执行既有 TimeFence 和重复记录规则，并在有限
预算内将状态变化、SystemMutationResult、SourceAdvance 原子提交。authority lookup
失败不能当作策略拒绝并推进 source。C1 还负责 Target 格式激活门、注册/策略后端装配、
closure 持久投影与重放、source 物理路由证明及 crash/recovery。上述职责不由接口存在
或内存测试夹具完成。Policy/Key authority 的生产实现必须满足 §1 的历史审批保留条件。

未授权注册/签名/actor/policy 使用 UNAUTHORIZED_SYSTEM_MUTATION；首次应用超过签名
retry deadline 使用 SYSTEM_MUTATION_RETRY_WINDOW_EXPIRED；完整性损坏失败关闭。
首次 Schedule 绑定继续使用 §06 的五个 domain 稳定码和 §08 的 Profile/授权稳定码。
新控制语义尚未接入活动 DelayShard：旧 decoder 拒绝 kind 15/16，旧 Store 将合法签名
的新 mutation 记录为 REJECTED / STALE_SYSTEM_MUTATION，重开后仍无新 grant/policy。
这证明未激活边界，不能将该拒绝结果在同一 mutation ID 下换参重放。

## 4. 上限与独立证据

| 对象 | canonical 保守上限 bytes | 独立最大合法输入 bytes |
| --- | --- | --- |
| policy | 1052039 | 1052033 |
| request branch | 3153314 | 3153224 |
| source body | 3153474 | 3153378 |

最大输入包括 1 MiB 物理证据 topic、256-byte Profile/cluster ID、完整宽度版本和时间、
32 controls + 32 permits。它们不是 A2 的完整 mutation envelope 或有限生产配置证明。
标准库 `generate-ndip3-target-membership-control-vectors.py` 独立计算 34 条向量，不读
Java 输出；`checkTargetMembershipControlVectors` 纳入常规 check。测试覆盖真实 Ed25519、
四类 policy、精确注册、角色/资源替换、遗漏组、历史 closure、UINT32MAX key、后端失败、
最大输入、旧 NV reader 和本地 RocksDB 重开。Broker/真实 Oxia 权威未在此认证。
