# NDIP-3 B2：执行与控制兼容契约

Status: Draft / IN_PROGRESS

本节细化原设计 §8.2–§8.7、§17.3 的 B2。已实现的是规范化引用对象、闭合编码和有界
注册规划；source-bound membership、完整 Schedule binding、通道冻结与 teardown
尚未闭合。本文不激活 Store format 2，不授予发送权限，不能作为 B7 接受凭证。

## 1. 一个物理 Target 与一个可共队类别

TargetPartitionId 仍只标识物理资源和 partition。Profile ID、version、retry、payload、
bucket、别名和 tenant 名称不进入 Target 身份，也不能单独创建执行域。

每个已绑定执行域保存一个固定的 offered contract。候选 Profile 提供 required contract；
已有类别能够满足该要求，且每条消息共享完整的发送控制与 permit 集合时，允许复用。
契约不相等不一定不兼容；覆盖判断必须核对完整字段，不能只比较 hash，也不能因
实际 Broker 看起来更强就临时提高已声明保证。更新 offered contract 不能就地改写
ACTIVE/DRAINING 的引用；必须按后续绑定/排空协议形成新 generation。

## 2. TargetDispatchCompatibility

闭合 canonical protobuf，schema=1，全部九个字段必填且只出现一次：

| field | 类型与内容 |
|---|---|
| 1 | uint32 schema=1 |
| 2 | TargetPartitionId[32] |
| 3 | 非零 authorizationScope[32]；服务端写入授权语义，不含 secret |
| 4 | 正整数 adapterEncodingVersion |
| 5 | DeliveryCapabilitySemantic 的完整 canonical body，不含 Profile envelope/ref |
| 6 | 非零 targetPrerequisitePolicyDigest[32] |
| 7 | 非负 uint64 minimumTargetTopicTtlMs，当前范围 0..Long.MAX_VALUE |
| 8 | 非负 uint64 minimumTargetTopicRetentionMs，同上 |
| 9 | SHA-256(domain bytes + canonical fields 1..8) |

hash domain 为 UTF-8 `nereus-delay-target-dispatch-compatibility` 加一个零 byte。
field 5 保留 Registry §5.1.1 的全部 12 个字段和能力分支约束；强能力的 evidence resource
遵守 B1 的物理资源边界，broker prerequisite/source-lock digest 必须非零。
嵌套 capability 上限 1049017 bytes，整个 dispatch 上限 1049187 bytes；独立最大宽度
向量实际 1049181 bytes。先校验总长度，再以 root≤9、capability≤12 的 field 上限解析。
未知字段、重复字段、非 canonical 顺序/数值、错误 hash 或超限全部拒绝。

`fromProfiles` 检验 destination/capability typed body、精确 capability ref、目标资源、
adapter、partition count 与 EXPLICIT_ONLY allowed list。Target projection 还须检验
物理 adapter，以及 Kafka transactional target/receipt 同一 authenticated cluster。
它不验证当前 Profile activation、credential lease、resource guard 或 membership authority。

### 2.1 offered.canServe(required)

| 维度 | 允许覆盖的必要条件 |
|---|---|
| Target、authorization scope、encoding、target prerequisite policy | 完全相同 |
| adapter、outcome、evidence resource 与 partition count | 完全相同；普通发送不能替代事务/去重，反向也不自动换约 |
| timing capability | offered bits 包含 required bits |
| evidence retention、dedup horizon、目标 TTL/retention | offered 的每一项最小保证 ≥ required 对应值 |
| maximum certified producer keys | offered 的受控 producer 总数上限 ≤ required 的认证安全上限 |
| broker prerequisite/source-lock digest、conformance/classifier version | 完全相同 |

producer 上限比较要求实际类别的 admission/通道配置严格兑现 offered ceiling；例如
候选认证至多 128 个 producer key，固定类别限制为 64 个可以服务它，固定类别限制为
256 个则不可以。这不是由 Profile 数量推导的上限，也不是允许绕过真实资源证据。
覆盖成立仍须有 source-bound 权威证明这些 offered 保证以及共同 credential 可用性。

Profile envelope ID/version、准备别名、bucket、消息大小上限及 retry 不参与归一化；
它们原有的单消息校验仍执行。凭据 generation/fingerprint/lease 不加入长期 compatibility
hash；授权语义等价和共同通道可使用性必须另行证明，不能凭两个相同 hash 推断。

## 3. TargetControlScope

闭合 canonical protobuf，schema=1；它描述稳定成员集合，不保存 mutable Pause/revision
或 permit 余量。只有完全相同的集合才可以共用一个类别 head。

| field | 类型与内容 |
|---|---|
| 1 | uint32 schema=1，必填 |
| 2 | TargetPartitionId[32]，必填 |
| 3 | source Shard[20] = RouteIncarnation[16] + partition u32be，必填 |
| 4 | 重复 ControlGroup，最多 32 个，按 (kind, unsigned id bytes) 严格递增 |
| 5 | 重复非零 permitGroupId[32]，最多 32 个，按 unsigned bytes 严格递增 |
| 6 | SHA-256(domain bytes + canonical fields 1..5)，必填 |

ControlGroup 是恰好两个字段：1 uint32 kind；2 非零 group ID[32]。kind 是闭合集合：
1 BINDING_SEND_CONTROL、2 TENANT_SEND_CONTROL、3 AUTHORIZATION_CONTROL。
单个 group canonical≤36 bytes，完整 scope≤2396 bytes、root≤68 fields；最大向量达到
2396 bytes。hash domain 为 UTF-8 `nereus-delay-target-control-scope` 加一个零 byte。
不排序修复外来数据，不接受重复 group、未知 kind、非 canonical bytes 或超限集合。

Target/source-Shard 共同控制门与统一 Target 预算是隐含前提；field 4/5 列出所有额外
会挡住单个候选的控制与 permit 组。空集合只允许在权威记录证明没有额外独立阻塞门
时使用。tenant admission quota 本身不必拆域，但独立发送 permit 必须出现。
同一授权语义却各自依赖独立凭据可用性的绑定，须通过不同 AUTHORIZATION_CONTROL
表达，或先证明可由同一受控通道执行；不得直接省略这一差异。

例如 A 先到期且独立 Pause，B 后到期且健康：两者 scope 不同，基础单域注册拒绝 B，
不将 B 写入 A 的公共前缀。存量转换输出冲突。注册不读取消息尾部来寻找 B，后续 E2
通过至多 K 个域 head 独立暴露它们。codec 只能证明集合的格式，完整性需权威证明。

## 4. 引用、Store key 和旧 reader 边界

| 对象 | meta key（34 bytes） | reserved NV type |
|---|---|---|
| TargetDispatchCompatibility | `0c 01 + digest[32]` | 18 |
| TargetControlScope | `0d 01 + digest[32]` | 19 |

TargetDomainState 的 dispatchCompatibilityRef/controlScopeRef 指向以上完整对象。
读取验证 exact key 或 expected ref、body hash、完整物理 Target projection；control
还核对 source Shard。错误引用/集合/域投影属于存储完整性错误，不可伪装成业务拒绝。
相同内容可复用不可变对象，但是否可回收必须考虑全部绑定、attempt 与恢复保护引用。
实际引用生命周期及写入由 C1 接入。七个 CF 不变；活动 Lane writer/reader 继续使用
format 1 和已注册 NV 1..11，有效 CRC 的 NV 18/19 也被当前 reader 拒绝。

## 5. 有界注册规划及 source 时序

`TargetDomainRegistration` 只返回 Plan，不写 Store、不消耗 source、不建立通道。
输入是精确 physical identity、queue snapshot、source Shard、全部非 VACANT 域的
完整 bound contracts、候选 requirements 和 activatedMaxSlots。基础激活上限=1，
schema 上限=64；传入 2..64 只供有界扩展规划测试，E2 runtime gate 前不可正式打开。

先验证所有 bound contracts 按 slot 顺序完整覆盖 ACTIVE/DRAINING，ref/native ref 和
generation 精确匹配，且没有重复的完整要求；缺失、额外和错误对象均为 integrity error。
然后按以下固定次序决策：

1. Target CLOSED 返回 TARGET_CLOSED。PAUSED 不阻止纯注册，也不会由注册打开 gate。
2. 在全部类别中选最小 slot 的 ACTIVE covering contract 复用；可满足的 DRAINING 域
   不遮住后方 ACTIVE。没有 ACTIVE 而有可满足的 DRAINING 时拒绝新绑定。
3. 否则复用最小可用 VACANT 槽位，generation 以 raw uint64 加一。UINT64_MAX 禁止回绕。
4. 没有可复用槽位但历史槽数小于 activatedMaxSlots，追加 slot=size、generation=1。
5. 容量已满时先报告存在但 generation 耗尽的 VACANT；否则基础单域报告不兼容，
   K>1 报告域上限。不得按 Profile 数量扩容或清除 generation 历史。

requirements 包含 optional Native policy ref：请求 Native 时必须有 Pulsar handoff
能力且 ref 精确匹配；请求没有 Native 路径可复用提供额外 Native 路径的类别，但不能
获得 Native permission。实际 Message/Policy 双重许可和签名仍由 B3/C1 执行。

Plan 绑定 queue revision 与 digest；两者任一变化必须重新规划。后续 C1 的 source
apply 必须在同一预算和提交屏障中校验 Owner/source/完整 authority/queue snapshot，
将拒绝 Result 与 SourceAdvance 原子提交。相同命令重放保持原结果；业务拒绝不阻塞
后续 source。预算未完成或快照变化是零写入本地重试，不能提前提交一个业务拒绝。

| stable code | 数值 | 条件 |
|---|---|---|
| TARGET_BINDING_INCOMPATIBLE | 0x1117 | 基础单域无可满足类别且无可分配槽位 |
| TARGET_EXECUTION_DOMAIN_LIMIT_EXCEEDED | 0x1118 | 显式 K>1 的域容量已满 |
| TARGET_EXECUTION_DOMAIN_DRAINING | 0x1119 | 只有排空中的匹配类别 |
| TARGET_EXECUTION_DOMAIN_GENERATION_EXHAUSTED | 0x111a | 满容量且空槽 generation 已耗尽 |
| TARGET_CLOSED | 0x111b | Target 已关闭 |

五者的 Retryability 均为 NEW_PREPARATION_REQUIRED；修正前提后使用新逻辑命令身份，
不能对已拒绝 source 记录换参重放。它们已注册，但活动 Lane 路径尚不发出这些结果。

## 6. 独立向量、能力覆盖及 B2 剩余交付

Python 标准库生成器 `scripts/generate-ndip3-target-compatibility-vectors.py` 独立计算
protobuf/CRC32C/hash。`checkTargetCompatibilityVectors` 在常规 check 中只读验证。
Java 检验 Kafka baseline/transactional receipt、Pulsar baseline/Managed Journal 四种
分支的 exact bytes/ref/key、控制集合、最大值和错误分支。它们是契约覆盖，尚未证明
任何新的运行时组合可激活；完整能力支持表和真实 Broker 认证继续由 B2/D1 闭合。

B2 仍须完成：source-bound group membership 与共同 credential/保证选择的授权记录；
完整 TargetScheduleBinding 及其 Profile/required/offered/source 引用；按 source Shard、
Target、执行域、channel slot/generation 固定的通道身份；旧 Admission 的 producer、
sequence、transaction、lease 与恢复域冻结；共享引用计数、请求归属、Owner loss 与
Producer fault teardown；完整注册/迁移拒绝时序与支持矩阵。C1/C2 实际原子写入和
通道池、E2 的 K 域 runtime、B3 Native policy、B6/F1 转换仍按原切片实施。
